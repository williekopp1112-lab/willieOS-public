Technical Decision Points

Fine-Tuning vs. Prompt Engineering Key Trade-off

Prompt engineering works well for common defect types (cracks, surface marks). Fine-tuning on customer-specific defect images improves recall for subtle defects like micro-fractures by 15-25%, but requires 200-500 labeled examples. Start with prompting, graduate to fine-tuning once the customer has labeled data.

RAG for Part Specs Architecture

Each part has different tolerance specs. RAG retrieves the correct spec sheet based on part number, injecting acceptable ranges into the system prompt. This avoids maintaining separate fine-tuned models per part type.

Latency Budget Constraint

Line speed dictates the latency budget. At 60 parts/minute, you have ~1 second per inspection. GPT-4o vision averages 300-800ms per image (low-detail mode). Edge preprocessing (crop, resize, select frames) keeps the API call within budget. Batching isn't viable for real-time reject decisions.

Edge vs. Cloud Roadmap Signal

Current deployment is cloud API with edge preprocessing. Full edge deployment (on-device inference) would eliminate latency and network dependency. OpenAI's distillation and model compression work signals this as a future capability. Today's architecture is designed to swap in edge inference when available.

What the solutions engineer needs to hear vs. what the COO needs to hear. Same truth, different vocabulary.

What the Engineer Sees
Internal alignment / Solutions

The Model

GPT-4o processes images natively through a unified transformer architecture. Vision tokens are embedded alongside text tokens. Low-detail mode encodes a 512×512 image as 85 tokens (~$0.0025 per image at current pricing). Function calling lets the model output structured defect classifications directly to the MES API.

  • 128K context window accommodates part spec docs via RAG
  • Function calling outputs structured JSON (defect type, confidence, bounding box)
  • Fine-tuning available for domain-specific defect patterns
  • Low-detail mode keeps latency under 500ms for most requests
What the CEO Hears
C-suite meeting

The Capability

The AI can look at a photo of a part and tell you, in under one second, whether it's good or defective. It speaks the same language as your factory systems. It knows the difference between a scratch that matters and one that doesn't, because it's read your quality specs.

  • Inspects at the speed of the line. No bottleneck, no batching.
  • Talks directly to your MES. Defective parts are rejected automatically.
  • Can be taught your specific defect types with a few hundred examples.
  • Costs less than a penny per part inspected.

What the Engineer Sees
Limitations and risks

Current Limitations

  • Latency variance: P99 can hit 1.2s under API load. Need edge preprocessing to buffer.
  • Hallucination risk: model may classify novel defects as "pass" if not in training data. Requires a fallback rule for low-confidence outputs (<0.7 confidence = route to human).
  • No on-device inference yet. Requires network connectivity to cloud API. Distillation/edge models on the roadmap but not GA.
  • Fine-tuning requires minimum 200 labeled images per defect class. Customer needs to build this dataset.
What the CEO Hears
Managed expectations

What to Expect

  • The AI starts strong on common defects. For rare or subtle issues, it gets smarter over time as your team labels examples.
  • When the AI isn't sure, it flags the part for a human instead of guessing. You stay in control.
  • Needs internet connectivity today. We're working on fully offline versions for air-gapped environments.
  • Pilot typically runs on one line for 30-60 days. Once the numbers prove out, rollout to additional lines is straightforward.
Setting: Handling the "What can't it do?" question from a skeptical CTO

"Honest answer: it's not perfect on Day 1. It catches the defects it's seen before. For the weird edge cases, the ones your best inspector spots twice a year, the system will flag them as uncertain and route them to a human. Over time, those edge cases become training data, and the system gets better. But I'd rather it ask a person than guess wrong."

"The bigger conversation is about connectivity. Today this runs through our API, which means you need a network connection. We're actively working on models that can run entirely on-site. When that's ready, we swap it in and you get the same accuracy without the network dependency."

Why This Matters for the Account Director Role

The job isn't to sell AI. The job is to sit between two worlds and make each one legible to the other.

With the research team, you need to know what the model can actually do, where the edges are, and what's coming. You need to know that low-detail mode keeps costs down and that function calling is how you integrate with factory systems. With the customer, you need to speak in outcomes. Not "128K context window" but "it reads your part specs automatically." Not "function calling" but "it talks to your factory systems." The technical depth lets you answer the hard questions without passing them to engineering. The business framing lets you hold a room of executives.
